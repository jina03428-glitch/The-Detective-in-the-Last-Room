AI 인터랙티브 추리게임 C.L.U.E. 제작 원칙
- C — Canon & Consistency: 사건의 진상과 설정은 일관되게 유지한다.
- L — Licensed & Lawful: 사용 권한이 확인된 자료만 사용한다.
- U — User Fairness: 플레이어가 합리적으로 추리할 수 있게 설계한다.
- E — Editorial Control: AI 결과물은 반드시 사람이 검토하고 책임진다.
1. 사건의 진상은 먼저 사람이 완성한다
AI가 범인과 사건의 진상을 플레이 도중 즉흥적으로 만들게 하지 않는다. 개발자는 게임을 제작하기 전에 다음 내용을 담은 사건 원본 문서를 완성한다.
- 범인
- 피해자와 용의자
- 범행 동기
- 범행 방법
- 사건 발생 시각
- 시간대별 인물 위치
- 사용된 도구
- 범인이 숨긴 내용
- 각 NPC가 알고 있는 사실
- NPC가 거짓말하는 이유
- 결정적인 증거
- 보조 증거
- 플레이어를 혼란스럽게 하는 증거
- 사건의 최종 결말
AI NPC는 사건 원본 문서 안에서만 대화해야 하며, 새로운 범인이나 핵심 증거를 마음대로 만들어서는 안 된다.
2. AI는 연기하고, 사건 시스템은 판정한다
AI의 역할은 NPC의 자연스러운 말투와 감정 표현을 담당하는 것으로 제한한다.
AI가 할 수 있는 일
- NPC의 성격에 맞는 답변 생성
- 플레이어의 다양한 질문 이해
- 알고 있는 정보를 자연스럽게 설명
- 긴장, 당황, 분노 등의 감정 표현
- 이미 정해진 거짓말과 회피 행동 수행
- 확보한 증거에 따른 반응 표현
AI가 하면 안 되는 일
- 새로운 용의자나 증거 생성
- 사건 시간표 변경
- 범행 방법 변경
- NPC가 알 수 없는 정보 공개
- 트리거가 발생하지 않은 단서 공개
- 확정된 사실과 모순되는 답변
- 엔딩 전에 범인을 직접 공개
- 플레이어의 추리를 무조건 정답으로 인정
- 실제 인물이나 기존 작품의 캐릭터를 흉내 내기
범인 판정, 증거 획득, 트리거 실행, 엔딩 결정은 AI가 아니라 게임 로직이 담당한다.
3. NPC는 제한된 기억만 가진다
NPC마다 별도의 정보 범위를 설정한다.
공개 정보: 처음부터 말할 수 있는 내용
개인 정보: 특정 질문을 받았을 때만 말하는 내용
숨긴 정보: 신뢰도나 압박 조건을 충족해야 공개되는 내용
거짓 진술: 미리 정해진 이유와 내용
금지 정보: 해당 NPC가 절대 알 수 없는 내용
감정 상태: 질문과 증거에 따라 변하는 반응
NPC가 알지 못하는 질문을 받으면 내용을 만들어내지 않고 다음과 같이 답해야 한다.
- “그 부분은 잘 모르겠습니다.”
- “제가 직접 본 것은 아닙니다.”
- “그 시간에는 그곳에 없었습니다.”
- “확실하게 기억나지 않습니다.”
4. NPC의 거짓말에도 이유가 있어야 한다
거짓말하는 NPC가 모두 범인이어서는 안 된다. NPC의 거짓말에는 다음과 같은 이유를 설정할 수 있다.
- 개인적인 비밀을 숨기기 위해
- 다른 사람을 보호하기 위해
- 사건과 무관한 잘못을 숨기기 위해
- 자신의 평판을 지키기 위해
- 범인의 협박을 받았기 때문에
- 기억이 불확실하기 때문에
- 범인을 잘못 의심하고 있기 때문에
거짓말은 반드시 다른 증거 또는 진술을 통해 확인할 수 있어야 한다.
5. 플레이어가 범인을 추리할 수 있는 공정한 사건을 만든다
정답을 맞히기 위해 필요한 핵심 단서는 게임 안에서 반드시 획득할 수 있어야 한다.
- 결정적인 증거를 숨겨진 유료 콘텐츠로 두지 않는다.
- 엔딩에서 처음 등장하는 증거로 범인을 설명하지 않는다.
- 플레이어가 확인하지 못한 정보를 정답 근거로 사용하지 않는다.
- 최소 두 가지 이상의 단서로 핵심 진상을 검증할 수 있게 한다.
- 분위기만으로 범인을 고르게 하지 않는다.
- NPC의 외모, 성별, 국적 등을 범인의 근거로 사용하지 않는다.
- 잘못된 추리에도 어떤 근거가 부족했는지 설명한다.
좋은 반전은 정보를 숨기는 것이 아니라, 이미 보여준 정보를 다른 의미로 해석하게 만드는 방식이어야 한다.
6. 선택은 사건의 경로를 바꾸되 기본 진상을 훼손하지 않는다
플레이어의 질문과 선택에 따라 다음 요소는 달라질 수 있다.
- 먼저 조사하는 장소
- 확보하는 증거의 순서
- NPC와의 관계
- 추가로 발견하는 비밀
- 돌발 상황의 발생 여부
- 용의자의 도주 여부
- 사건 해결에 걸린 시간
- 최종 결말
하지만 기본 사건의 범인과 범행 사실은 플레이 중 임의로 변경하지 않는다. 범인이 플레이마다 달라지는 모드를 만들고 싶다면 처음부터 범인별로 완성된 사건 원본을 별도로 제작해야 한다.
7. 돌발 상황은 조건과 결과를 명확하게 설정한다
모든 돌발 상황은 다음 구조로 관리한다.
트리거 조건
→ 발생 이벤트
→ 화면 및 NPC 변화
→ 획득하거나 잃는 정보
→ 이후 사건에 미치는 영향
→ 중복 발생 가능 여부
예시:
조건: 플레이어가 창고 열쇠를 획득하고 행동 횟수가 10회를 넘음
사건: 정전 발생
변화: 복도 CCTV가 일시적으로 중단됨
추가 정보: 정전 직전 창고에 들어간 인물 확인 가능
결과: 특정 NPC가 진술을 변경함
중복 발생: 불가능
무작위로 발생하는 돌발 상황도 사건의 핵심 논리를 깨뜨리면 안 된다.
8. 증거에는 출처와 역할을 기록한다
모든 증거품에는 다음 정보를 저장한다.
- 증거 이름
- 발견 장소
- 발견 조건
- 실제 소유자
- 사건에서의 의미
- 연결되는 NPC
- 진짜 증거인지 혼란용 증거인지
- 특정 NPC에게 보여줬을 때의 반응
- 최종 추리에서 사용할 수 있는지
- 이미지와 음원의 제작 출처
증거를 조사하기 전과 후의 설명도 구분한다.
조사 전: 깨진 손목시계다.
조사 후: 시계는 오후 8시 42분에 멈춰 있으며, 유리 안쪽에서 붉은 섬유가 발견되었다.

9. 진행 불가능 상태를 만들지 않는다
플레이어가 잘못된 선택을 하더라도 핵심 단서를 영구적으로 잃어 사건을 해결할 수 없는 상태가 되지 않도록 한다.
- 중요한 증거에는 대체 획득 방법 제공
- NPC가 떠나도 기록이나 다른 증언으로 정보 획득 가능
- 필수 증거를 실수로 삭제할 수 없게 처리
- 일정 시간 동안 진행이 없으면 단계별 힌트 제공
- 사건 종료 전 미확인 핵심 항목 안내
- 자동 저장과 이전 시점 불러오기 제공
힌트는 바로 정답을 알려주지 않고 다음과 같이 단계적으로 제공한다.
1. 확인할 장소 제안
2. 관련 NPC 제안
3. 비교해야 하는 진술 제안
4. 핵심 모순 설명
10. 현실 범죄를 따라 할 수 있는 상세 정보는 줄인다
추리게임의 몰입감은 유지하되 실제 범죄를 구체적으로 따라 할 수 있는 내용은 제한한다.
- 위험한 도구의 구체적인 제작 방법 제외
- 범죄 은폐 방법을 단계별로 설명하지 않음
- 실제 보안 시스템을 우회하는 방법 제외
- 특정 개인이나 집단을 범죄자처럼 묘사하지 않음
- 잔혹한 장면은 필요한 수준에서만 표현
- 범죄 피해를 가볍게 소비하거나 미화하지 않음
- 연령에 맞는 콘텐츠 경고 제공
저작권을 지키기 위한 프로젝트 규칙
11. “검색해서 나온 자료”는 무료 자료로 간주하지 않는다
Google 이미지, Pinterest, 블로그, 유튜브 등에서 발견한 이미지와 음원을 출처 없이 사용하지 않는다.
사용 가능한 자료는 다음 중 하나로 제한한다.
- 팀이 직접 제작한 자료
- 제작자와 계약하여 받은 자료
- 상업적 이용과 수정이 허용된 라이선스 자료
- 이용 조건을 확인한 오픈 라이선스 자료
- 퍼블릭 도메인 여부를 확인한 자료
- 해당 AI 서비스 약관상 프로젝트 이용이 허용된 결과물
단순히 출처를 표시했다고 해서 모든 저작물을 자유롭게 이용할 수 있는 것은 아니다. 국내 저작권법상 공정이용 여부는 이용 목적, 저작물의 종류, 사용 비중, 시장에 미치는 영향 등을 종합적으로 판단합니다. 따라서 프로젝트에서는 “교육용이니까 괜찮다”라고 임의로 판단하지 않는 것을 원칙으로 합니다. 국가법령정보센터 저작권법 제35조의5
12. 기존 추리 작품을 바꿔 쓰지 않는다
다음 요소를 기존 영화, 소설, 게임에서 그대로 가져오지 않는다.
- 사건의 핵심 반전
- 범행 방법과 증거 조합
- 인물 관계
- 캐릭터 이름과 외형
- 고유한 세계관
- 대표적인 대사
- 장소 구성
- UI와 게임 화면
- 작품을 상징하는 음악과 효과음
“유명 탐정 캐릭터처럼 만들어줘”보다 다음과 같이 독자적인 속성을 조합한다.
말수가 적고 관찰력이 뛰어나지만 사람의 얼굴을 잘 기억하지 못하는 신입 기록 분석관

장르의 일반적인 요소는 참고할 수 있지만, 특정 작품의 구체적 표현을 복제하지 않는다.
13. 실제 인물과 실제 사건을 무단으로 사용하지 않는다
- 실제 사건을 이름만 바꿔 그대로 재현하지 않는다.
- 실제 피해자와 유가족을 연상시키는 정보는 사용하지 않는다.
- 살아 있는 사람을 범인이나 용의자로 묘사하지 않는다.
- 유명인의 얼굴이나 목소리를 무단으로 합성하지 않는다.
- 실화를 참고해야 한다면 여러 자료에서 일반적인 구조만 연구하고 사건과 인물은 새롭게 창작한다.
- 민감한 실제 사건은 오락 콘텐츠로 소비하지 않는다.
14. AI에게 특정 작가의 화풍이나 문체 복제를 요청하지 않는다
법적으로 스타일 자체의 보호 여부와 별개로, 프로젝트 자체 기준은 더 엄격하게 설정한다.
피해야 할 요청:
- “특정 게임의 캐릭터처럼 만들어줘.”
- “특정 작가의 그림체로 그려줘.”
- “유명 배우의 목소리로 말하게 해줘.”
- “특정 추리소설 작가의 문체로 작성해줘.”
권장 요청:
- 시대, 색상, 분위기, 재료, 구도와 같은 일반적인 시각 특성 설명
- 캐릭터의 성격, 의상, 직업, 표정 등을 직접 조합
- 팀에서 제작한 콘셉트 시트를 기준 이미지로 사용
- 생성 후 사람이 형태와 설정을 수정해 프로젝트 고유성을 강화
15. AI 결과물은 그대로 최종 작품으로 사용하지 않는다
AI가 만든 시나리오, 캐릭터, 이미지, 대사는 다음 과정을 거친다.
AI 초안 생성
→ 기존 작품과의 유사성 확인
→ 사람이 설정과 표현 수정
→ 사건 전체와의 모순 검사
→ 권리와 출처 검토
→ 최종 승인
국내 저작권법은 저작물을 인간의 사상 또는 감정을 표현한 창작물로 정의합니다. 따라서 AI를 활용한 창작물은 사람이 어떤 선택·수정·배열·창작적 기여를 했는지 기록해 두는 것이 중요합니다. 국가법령정보센터 저작권법 제2조, 한국저작권위원회 생성형 AI 활용 저작물 등록 안내서
16. 모든 외부 자료는 저작권 장부에 기록한다
프로젝트에 포함되는 이미지, 음악, 효과음, 폰트, 아이콘, 코드 라이브러리는 다음과 같이 기록한다.
항목	기록 내용
자료 이름	파일명과 게임 내 사용 위치
자료 유형	이미지·음악·폰트·코드 등
제작자	제작자 또는 제공 기관
출처	원본 페이지 주소
라이선스	구매·CC BY·CC0·MIT 등
상업적 이용	가능·불가능
수정	가능·불가능
출처 표시	필요한 표기 방법
확인 날짜	라이선스를 확인한 날짜
증빙	구매 영수증 또는 라이선스 화면
AI 사용	사용한 모델과 생성 날짜
검토자	최종 사용을 승인한 사람


출처 페이지가 사라질 수 있으므로 라이선스 화면이나 구매 증빙도 함께 보관한다.
17. 라이선스 조건을 자산별로 확인한다
특히 다음 항목을 별도로 확인한다.
- 폰트를 앱이나 게임에 포함할 수 있는지
- 음악을 영상뿐 아니라 인터랙티브 게임에 사용할 수 있는지
- 무료 아이콘의 출처 표시가 필요한지
- AI 생성 서비스를 상업적으로 사용할 수 있는지
- 오픈소스 코드를 수정·배포할 수 있는지
- 캐릭터 에셋을 여러 프로젝트에서 사용할 수 있는지
- CC 라이선스가 수정이나 상업적 이용을 허용하는지
“무료 다운로드”와 “자유로운 상업적 이용”은 같은 의미가 아니다.
18. 팀원의 창작물 소유권을 미리 정한다
팀 프로젝트라면 개발 전에 다음 사항을 합의하고 문서로 남긴다.
- 시나리오 작성자
- 캐릭터 디자이너
- 프로그래머
- 음악 및 효과음 제작자
- AI 프롬프트 및 결과물 편집자
- 프로젝트 종료 후 결과물의 소유자
- 포트폴리오 사용 범위
- 상업화할 경우 수익 배분
- 팀원이 탈퇴했을 때 해당 작업물을 계속 사용할 수 있는지
공동 작업물은 “같이 만들었으니 알아서 사용할 수 있다”고 가정하지 않는다.
19. 사용자 대화를 AI 학습 자료로 임의 사용하지 않는다
플레이어와 NPC의 대화에는 개인적인 내용이 포함될 수 있다.
- 필요한 대화만 저장
- 저장 목적과 기간 안내
- 비밀번호나 연락처 입력 방지
- 삭제 기능 제공
- 모델 제공자에게 전송되는 정보 안내
- 사용자 동의 없이 별도 AI 학습 자료로 활용하지 않음
- 로그에 개인정보가 들어가지 않도록 필터링
- 공개 대화 데이터로 사용할 때 별도 동의 획득
20. 공개 전 저작권 검수 절차를 거친다
배포 전 다음 질문을 모두 확인한다.
- 모든 캐릭터와 사건은 독자적으로 제작했는가?
- 실제 사건이나 특정 작품과 지나치게 유사하지 않은가?
- 이미지, 음악, 폰트의 이용 권한이 있는가?
- 출처 표시가 필요한 자료를 표시했는가?
- 오픈소스 라이선스 문서를 포함했는가?
- AI 생성물의 제작·수정 기록이 남아 있는가?
- 유명인의 얼굴이나 목소리를 사용하지 않았는가?
- 팀원 및 외주 제작자와 이용 범위를 합의했는가?
- 플레이어 대화와 개인정보 처리 방침이 있는가?
- 문제가 발견된 자료를 빠르게 교체할 수 있는가?
